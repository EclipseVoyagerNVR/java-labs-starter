## Инварианты модели

### `BankAccount`

- `balance >= 0` после создания и после любой операции.
- `deposit` и `withdraw` принимают только строго положительные суммы.
- `withdraw` не может списать больше остатка.
- Баланс доступен только через `getBalance()`; setter не существует.

### `DataSample`

- `id` — не `null` и не пустой (`SampleId` проверяет это при создании).
- `label` — не `null` и не пустой.
- `status` — не `null`; изменить его можно только через `changeStatus`.
- `isReady()` возвращает `true` только для `SampleStatus.READY`.
- `features` — не `null`, не пустой массив и содержит только конечные числа.
- Массив копируется в конструкторе и в `getFeatures()`, поэтому внешний код не может изменить состояние модели.
- `averageFeatureValue()` работает с непустым массивом, который гарантирован конструктором.
- `normalizedFeatures()` возвращает новый массив со значениями от `0` до `1` (min-max нормализация); для одинаковых признаков возвращаются нули. Исходный объект не изменяется.
- Модель не читает консоль и не печатает.

## Почему `SampleId` — значение

`SampleId` неизменяем: единственное поле `value` объявлено `final`, setter отсутствует. Два объекта с одинаковой строкой равны по `equals` и имеют одинаковый `hashCode`, то есть их различает только значение, а не личность объекта. Такой тип удобно использовать как идентификатор: его можно безопасно передавать и сравнивать, не опасаясь изменения извне.
